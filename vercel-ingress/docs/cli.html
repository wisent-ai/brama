Brama CLI command reference

CLI¶

The brama binary is the gateway, its local diagnostics, and its operator repair surface. Billable commands require explicit cost acknowledgement, credential mutations require an audit reason, and no command prints credential material. This tree follows the public dispatcher in Brama 0.2.41.

Root invocation¶

brama <COMMAND>

A top-level command is required. Use brama --help or brama help [COMMAND]... to print the same tree from the installed build.

Complete command tree¶

  • brama version — print secret-free product and build identity as JSON.
  • brama serve — start the OpenAI-compatible HTTP server.
  • brama onboard — run the first-use journey and optionally receive one real model response.
  • brama adopt --from <FILE> … — review and atomically adopt selected aliases from an existing Brama route registry.
  • brama test — run one acknowledged test inference through the agent subscription path.
  • brama detect — detect local hardware and print a model recommendation.
  • brama mcp — serve the read-only stdio MCP hardware-detection surface.
  • brama aliases [--json] [--strict] — report every declared model alias, the route behind it, and whether this gateway can serve it; --strict exits non-zero when any cannot.
  • brama subscriptions [--json] [--refresh-usage] — report the subscription pool this gateway routes over: every subscription, its state, its usage window and its failure, optionally reading current free provider reports.
  • brama routes <COMMAND> — act on this gateway's inference-route registry.
    • brama routes migrate [--file <FILE>] [--json] — rewrite the route registry into the current document shape: keep the known top-level fields, validate, and commit with the same atomic owner-only replacement every other registry write uses. Idempotent.
  • brama subscription <COMMAND> — enter the credential mutation group.
    • brama subscription refresh <PROVIDER> --reason <REASON> [--json] — refresh one provider's OAuth grants now.
    • brama subscription sign-in <PROVIDER> --reason <REASON> [--subscription-id <ID>] [--login-item <LOGIN_ITEM>] [--login-timeout-ms <MILLISECONDS>] [--json] — drive one exact Weles row and prove it with a refresh.
  • brama collect-task-quality --agent-id <ID> --task <KEY> --prompt <TEXT> [--expected-exact <TEXT>] [--expected-contains <TEXT>] [--persist] [--max-models <N>] --allow-provider-cost — collect deterministic task-quality evidence.
  • brama help [COMMAND]... — print root or command-specific help.

Safety boundaries¶

version, detect, subscriptions without --refresh-usage, and help are read-only. --refresh-usage reads the plan-usage capability, which reads provider reports and persists their outcome through Brama's normal credential handling; it starts neither a sign-in nor model inference. mcp exposes local detection only. adopt is review-only unless --apply is combined with an exact selection; it never reads credential material or calls a provider. routes migrate reads and rewrites one registry file and contacts no provider. test, the provider-requesting part of onboard, and collect-task-quality require --allow-provider-cost. subscription refresh and subscription sign-in require --reason and journal their verdicts. Each linked command page states its exact inputs, output and state effect, and relevant refusal text.
