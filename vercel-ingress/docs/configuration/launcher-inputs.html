Brama configuration reference

Launcher inputs¶

src/release/bin/start-with-skarbiec is the managed entry point. It reads operator-owned policy, provisions or verifies this installation's trust material, derives the security-bearing variables the gateway reads, and then execs brama serve. This page lists what the launcher itself requires. What it hands to the gateway is on Gateway inputs.

Required inputs¶

The launcher reads BRAMA_SERVICE_ENV_FILE (default ~/.config/brama/service.env) first, then requires:

  • BRAMA_GNUPG_HOME — the service's GnuPG home. Startup ends without it; no other home is used in its place.
  • SKARBIEC_VAULT_FILE — the authorized encrypted vault.
  • BRAMA_CONTROL_CONFIG — the authoritative non-secret service policy document. The launcher reads services.brama.{allowed_models,model_aliases,required_provider_capabilities} and rejects policy that is absent, malformed, or inconsistent with itself.

An input that is missing, malformed, duplicated, or contradicted by another input ends startup with a message naming it. The launcher does not proceed on a partial policy and does not choose a value the operator did not declare.

What it derives and provisions¶

From those three inputs the launcher derives the identity and policy variables the gateway reads, including the wisent-backend client's exact four-alias grant, and it provisions or verifies this installation's trust material.

VariableDefaultMeaning
BRAMA_SKARBIEC_CONFIG_DIRper installationthis installation's Skarbiec configuration directory
BRAMA_PROOF_KEY_FILE~/.stado/brama-proof.keythe installation proof key, provisioned or verified at startup
BRAMA_CAP_SOCKET~/.stado/run/brama-capability.sockowner-bound capability socket the launcher starts before the gateway
BRAMA_RUNTIME_DIR/tmp/brama-skarbiec-<installation>holds the per-installation socket, GnuPG, and receipt directories
BRAMA_RENEWAL_ENABLEDonwhether the credential renewal loop is started

The launcher also seeds the route registry file when it is absent, creating it owner-only and empty rather than guessing routes. Its path and shape are on Route registry; an existing file written against an older shape is moved to the current one by brama routes migrate, which keeps only the known top-level fields, validates the result, commits it with the same atomic owner-only replacement, and prints it.

Capability material is issued, not configured¶

Runtime capability IDs are freshly issued from vault bindings at final use. The launcher clears any capability seeds it finds in the environment before it execs the gateway. Never write capability IDs or provider credentials into the non-secret env file: they belong to the vault and to the capability socket, and a value placed in the env file is cleared rather than honoured.

deploy/*.env.example documents the operator-facing subset of these inputs. Security explains the trust boundary the capability socket enforces.

Applying a change¶

Restart after any startup policy change. The gateway re-reads the route registry per request, but it does not re-read client identities, the alias policy, or capability maps in place, so a change to those takes effect at the next start. Runbook has the restart sequence and the checks to run afterwards.
