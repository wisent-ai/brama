Brama changelog: unreleased pool membership changes

Unreleased: pool membership¶

Committed changes that carry no release coordinate yet and decide which ids the subscription pool counts as its members. The other unreleased subscription changes are on unreleased subscription changes.

Unreleased: the pool lists only the vault's members¶

Every id that ever served a request through the gateway, test and renamed ones included, stood in brama subscription list beside the operator’s real accounts as undiscovered. The pool now holds what the vault lists, plus retired members, which still say why they left. An id only the usage history remembers is answered apart under remembered ({id, provider}), counted by no lease, session limit or purchase shortage, printed under remembered by the usage history only, not pool members and dropped with brama subscription forget.

Brama Desktop’s Subscription Pool screen lists them under the purchase panel in Remembered by the usage history only, each with Forget, which takes a typed reason and runs the same forget; the member inspector no longer has a Not discovered state, and an incomplete pool read no longer keeps such an id among the members. Real test: tests/subscriptions/journeys/forget_remembered_member.sh.
