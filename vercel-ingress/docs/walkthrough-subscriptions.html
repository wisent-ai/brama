Reading and repairing subscription usage¶

Use Brama's native commands or Brama Desktop. The commands below describe the product workflow; they are not captured execution results.

Read the recorded state

brama subscriptions --json

The response includes ok, observed_at_ms, errors, and providers. Each account carries its identity, credential state, actual plan windows, observation/reset times, and latest usage_check. A live credential alone is not proof of current usage.

Refresh free usage reports

brama subscriptions --refresh-usage --json

In Desktop choose Refresh usage on Subscriptions or Subscription Pool. Both use the same Brama function, which obtains credentials from Skarbiec and reads the provider's own report without sending a model request. Expired OAuth grants are renewed when possible; sign-in is never opened as a side effect.

Read failures without losing successful accounts

An incomplete report has ok: false and the CLI exits 1. errors preserves the failed operation, actual cause, account and attempt time. HTTP 200 alone does not mean success. A failing account does not hide successful accounts, and retained old measurements are visibly stale. Skarbiec failure is not an empty inventory; absent or malformed metrics are not zero usage. If Brama cannot answer, Desktop reports that connection failure itself instead of displaying a healthy empty screen.

Sign in only the account that requires it

brama subscription sign-in codex --subscription-id <subscription-id> --login-item <login-item> --reason 'replace the provider-refused grant' --json

The equivalent Desktop action is Sign in on the selected account. Weles performs the login on the Stado-selected host. Brama checks the account mapping and requires a successful refresh of that exact subscription; a different working account cannot make the operation succeed.

After a successful sign-in, refresh usage again. A provider rejection, unavailable Weles worker or failed Skarbiec write remains an explicit error, not an instruction to infer success from stored metadata.

See the CLI report contract, sign-in refusals, and HTTP result semantics.
