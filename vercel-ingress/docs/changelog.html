Brama changelog

Changelog¶

All notable Brama changes are documented here: what each release changed, why it changed, and what an operator has to do about it. Brama follows Semantic Versioning and the pre-one compatibility policy in RELEASE.md. This page is the index; the entries themselves are on the three pages below, newest first.

Older entries describe the contract as it stood at the time. Where a later change replaced it — most recently the route contract, under which an alias resolves to exactly one route — the entry says so and links the change that replaced it.

Unreleased¶

Unreleased changes holds the five entries that are committed but carry no published release coordinate yet:

  • an alias resolves to exactly one route, the registry document keeps schema_version, deployments and routes only, and brama routes migrate moves an existing registry file to that shape;
  • subscription plan usage replaces four invocations with POST /v1/plan-usage;
  • the subscription pool replaces eleven invocations with one capability and one leaf command;
  • the backend alias is the client's name, wisent-backend;
  • subscription usage and failure reporting across the CLI and Brama Desktop.

Published releases¶

Released 0.2.77 to 0.2.42 covers 0.2.77 (the managed backend identity derived from the required backend aliases), 0.2.76 (the managed launcher's aliases, and reviewing and adopting existing route configuration) and 0.2.42 of 2026-08-27, the large re-cut of 0.2.41 that carried streaming, the Anthropic Messages and OpenAI Responses ingress, plan usage read from the providers' own reports, credential refresh and classification, the readiness endpoints, and the archive that no longer ships a signing key.

Released 0.2.5 to 0.2.2 covers 0.2.5, 0.2.4 and 0.2.3 of 2026-08-05 — a shared HTTP client, routes-file validation on the snapshot path, and the desktop control plane — and 0.2.2 of 2026-08-04, which established the documented product contract: error codes, attempt bounds, request limits, public-surface versioning and immutable release provenance.

What a release coordinate means¶

A published coordinate is immutable, and a tag alone is not a release: a tagged revision whose release workflow did not finish leaves a coordinate with nothing installable behind it. The machine-maintained records are released-surface.json and the GitHub Releases list; release and support policy states how a version is chosen and how long it is supported.
