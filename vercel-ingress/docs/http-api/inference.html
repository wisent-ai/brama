Brama HTTP API reference

Inference¶

Five paths spend model quota: three chat dialects that share one routing decision, and two typed endpoints. All five require a bearer and an accepted transport (transport and identity).

The three inference dialects¶

POST /v1/chat/completions, POST /v1/messages and POST /v1/responses are one workflow. Identity, allowlist, alias resolution, selector semantics, billing ownership and the error contract are identical; only the request and answer shapes differ.

Each requires a model naming an allowed alias, a canonical provider/model route, or a selector. The alias names exactly one route, that route is attempted once, and its answer is the answer to the request; when it refuses, the refusal is what the caller receives and no other route is attempted. An alias that cannot serve is refused before any provider is contacted, with the 503 alias_unserviceable body in the refusal envelope.

Shared validation¶

  • A request with no model is 400 missing field `model`, and a bare vendor name is 400 model must be a canonical provider/model route or a supported selector (both captured).
  • max_tokens is 1024 when the request omits it, and a stated value outside 1..32768 is refused with max_tokens must be between one and 32768.
  • temperature is 0.7 when the request omits it, and a stated value is refused unless it is finite and no greater than two, with temperature must be finite and between zero and 2.
  • An empty conversation is refused with messages must not be empty.

POST /v1/chat/completions¶

Accepts exactly model, messages, max_tokens, temperature, tools, tool_choice, billingTarget (providerId/accountId/subscriptionId) and stream. An unknown field is refused with the deserializer's own sentence (captured):

400 invalid JSON: unknown field `frequency_penalty`, expected one of `model`,
`messages`, `max_tokens`, `temperature`, `tools`, `tool_choice`,
`billingTarget`, `stream` at line 1 column 93

Success (captured):

{"choices":[{"finish_reason":"stop","index":0,
  "message":{"content":"...","role":"assistant"}}],
 "id":"chatcmpl-...","model":"<route>","object":"chat.completion",
 "usage":{"completion_tokens":7,"prompt_tokens":9,"total_tokens":16}}

The model in the answer is the route that served the request, which is the one route the named alias resolves to.

With "stream": true the answer is a text/event-stream of chat.completion.chunk frames: a role delta first, then content deltas, a finish_reason frame, a usage frame, closed by data: [DONE] (captured in the standalone walkthrough).

POST /v1/messages¶

The Anthropic Messages dialect over the same routing decision. It accepts the Anthropic request shape: model, max_tokens, messages, system, tools and streaming. Anthropic fields the provider-neutral request cannot hold — stop sequences, cache-control hints, non-function tool types — are accepted and have no effect on the attempt; no approximation of them is sent in their place. Success (captured):

{"content":[{"text":"...","type":"text"}],"id":"msg_...",
 "model":"<route>","role":"assistant","stop_reason":"end_turn",
 "stop_sequence":null,"type":"message",
 "usage":{"input_tokens":9,"output_tokens":7}}

Streaming emits message_start, content_block_*, message_delta and message_stop events, with no [DONE] sentinel.

POST /v1/responses¶

The OpenAI Responses dialect, with input in place of messages. Reasoning options and stored-response identifiers are accepted and have no effect on the attempt. Success (captured):

{"created_at":...,"id":"resp_...","model":"<route>","object":"response",
 "output":[{"content":[{"annotations":[],"text":"...","type":"output_text"}],
   "id":"msg_...","role":"assistant","status":"completed","type":"message"}],
 "status":"completed",
 "usage":{"input_tokens":9,"output_tokens":7,"total_tokens":16}}

Streaming emits response.* events closed by response.completed.

Streaming commit rule¶

Everything that can change about a request — which credential redeems it, which account is billed — is settled before the first byte reaches the caller. Once a byte has been written, the generation is committed: a stream that ends without its terminal event was cut after commit, and Brama has already stopped. It does not resume a committed generation anywhere, and the caller sees the truncated stream and decides what to do about it.

Streaming a model reachable only through the shared catalogue is refused as 400 invalid_request before any provider is contacted.

POST /v1/embeddings¶

A typed, alias-only endpoint on the wisent-backend/embeddings route. It accepts exactly model, input, encoding_format (float or base64), dimensions and user; its shape refusals are invalid embedding input and invalid embedding encoding format. Success is the OpenAI embeddings shape: object: "list", data[].embedding, usage.

On a deployment whose registry declares no embeddings alias, the captured answer is 500 {"code":"internal_error","message":"embedding alias missing"}. Declaring the alias is a registry write (PUT /v1/admin/routes); an existing registry document is brought to the current shape by brama routes migrate.

POST /v1/moderations¶

A typed, alias-only endpoint on wisent-backend/moderation. It requires model and input, and answers invalid moderation input on a shape error. Success is the OpenAI moderations shape.

Which aliases the presenting bearer may name, and which of them can serve right now, is GET /v1/aliases. Which concrete models the caller can execute is GET /v1/models.
