Brama CLI command reference

brama decide¶

Ask one typed decision from a shell: a state and a set of typed questions in, one typed answer each out. It resolves the alias through the same route registry the gateway reads and dispatches through the same engines POST /v1/decisions uses, so what it prints is what a caller would have received.

Invocation¶

brama decide --state <STATE> --questions <QUESTIONS> [--model <ALIAS>] [--agent-id <ID>] [--json] --allow-provider-cost
InputRequired/defaultMeaning
--state <STATE>requiredThe state to decide on. A literal string, @FILE to read a file, or - to read standard input.
--questions <QUESTIONS>requiredThe questions object, exactly as the endpoint takes it. A literal JSON string, @FILE, or -.
--model <ALIAS>optional; decision-modelWhich decision alias answers. Only decision-model and best-decision-model are accepted.
--agent-id <ID>optional; wisent-appWhose subscription pays when the alias resolves to best. Ignored for a canonical route, which this deployment's own capability pays for.
--jsonoptional; offPrint the answer document instead of human-readable lines.
--allow-provider-costrequired to send anythingAcknowledge that this performs a billable provider request.

Why it exists¶

Two moments the HTTP surface cannot cover. Before a gateway runs, an operator has to know whether the route behind a decision alias answers at all; and while diagnosing one that stopped, the question is which of the alias, the route or the model broke. This command answers both against the real route, and its refusals are the endpoint's own sentences.

What it reads and writes¶

It reads the route registry — BRAMA_INFERENCE_ROUTES_FILE, else ~/.config/brama/inference-routes.json — and the launcher's alias table when the shell carries one, exactly as brama aliases does. It writes nothing. The provider credential is redeemed at final use through Skarbiec, the same cascade the gateway uses.

Output and state¶

One real run, against decision-model routed to openrouter/openai/gpt-4o-mini:

$ brama decide --model decision-model --allow-provider-cost \
    --state "Help! My payouts have been failing for 3 days." \
    --questions @questions.json
Model: decision-model
Route: openrouter/openai/gpt-4o-mini (chat-distribution)
department               choice billing  confidence 0.70  [billing=0.70 sales=0.10 technical=0.20]
is_urgent                noul 1.0000  confidence 1.00
severity                 score 2.1000  confidence 0.50  [0=0.00 1=0.20 2=0.50 3=0.30]
Tokens: 247 in / 106 out
Latency: 2514ms

With --json the answer is the endpoint's own document: model, route, engine, answers and usage. Exit code is 0 when every question was answered inside the schema the caller declared.

Refusals¶

SentenceMeaning
refusing a billable decision without explicit --allow-provider-costNothing was sent. Nothing is spent by running this command by accident.
--model must be `decision-model` or `best-decision-model`Only the two decision aliases reach this shape.
--questions is not JSON: <reason>The questions argument, file or standard input did not parse.
the question's own refusal, such as question `mood` declares unsupported type `vibe`: a question is a noul, a choice or a scoreThe same validation the endpoint performs, before any provider is contacted.
alias `decision-model` is a decision alias this gateway knows but no route is declared for it; declare one with `brama routes set decision-model <provider/model>` or `PUT /v1/admin/routes`The alias has no route here.
provider refused: <the provider's own sentence>The route was reached and refused — no credits, a rate limit, an unavailable credential.
decision_contract_violated: <what was wrong>The model answered outside the declared schema. The repair is the route, not the request.

Every refusal exits 1 and prints on standard error.
