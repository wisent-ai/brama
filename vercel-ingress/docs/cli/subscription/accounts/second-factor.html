Brama CLI command reference

brama subscription second-factor¶

Report what the latest provider sign-in observed and whether Skarbiec reports a usable authenticator seed. These are separate observations: an account can require a phone approval without a stored seed, and a successful sign-in alone does not prove that two-factor authentication is disabled.

Invocation¶

brama subscription second-factor [--provider <PROVIDER>] [--json]
InputRequired/defaultMeaning
--provider <PROVIDER>optional; every providerNarrow the report to one provider.
--jsonoptional; offPrint the report document instead of lines.

Output and state¶

<N> account(s) asked for a second factor, <N> did not ask in the observed sign-in, <N> unobserved
  <provider> <account> -> needs a second factor | not requested in the observed sign-in | unobserved; seed <state>
    <evidence>

With --json: {required, not_required, unknown, accounts: [{provider, account, login_item, required, method, seed, seed_error, evidence}]}. required is true, false or null. False means no challenge was requested in the observed sign-in; null means the sign-in supplied no challenge observation. method distinguishes an observed phone approval from an authenticator challenge. A missing login reports no_login_declared, not a missing seed.

The command reads the pool and vault metadata, prints no secret and writes nothing. A failed seed inspection reports the actual operation and error. In pool responses, an unavailable seed observation is null with seed_error; Brama Desktop displays it in the selected account's Second factor section rather than showing an absent seed.

Refusals¶

A pool or vault read that fails prints its own sentence on standard error and exits 1. An unknown argument exits 2.
