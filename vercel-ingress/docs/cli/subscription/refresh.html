Brama CLI command reference

brama subscription refresh¶

Run the gateway’s credential refresh path now for every usable subscription held for one provider, without the background sweep’s expiry window.

Invocation¶

brama subscription refresh <PROVIDER> --reason <REASON> [--json]
InputRequired/defaultMeaning
<PROVIDER>requiredProvider whose grants are refreshed, normally codex, claude-code, or kimi.
--reason <REASON>requiredNonempty audit reason recorded beside the verdict.
--jsonoptional; offPrint JSON instead of labeled lines.

Output and state¶

The verdict contains provider, attempted, result (refreshed or failed), and detail. The command may rotate OAuth grants, updates the credential usage ledger, and journals completed verdicts with their reason. Retired subscriptions are excluded. It exits 0 only when every attempted credential was obtained; a partial refresh remains a failure and preserves each account's refusal. An inventory failure reports the actual discovery error instead of pretending there are no accounts.

Refusals¶

An empty provider is refused with a provider is required; an empty reason with --reason must say why this refresh is being run. No usable row produces a failed verdict whose detail starts no usable `<provider>` subscription is in this deployment's pool. An API-key provider produces `<provider>` subscription credentials are API keys rather than OAuth grants, so no refresh path exists for them: replacing one means storing a new credential in the vault. Provider or credential refusals are quoted in detail; failure exits 1.

See the command group or the CLI tree.
