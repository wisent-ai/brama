Brama CLI command reference

brama subscription lease release¶

End one lease by its id, or every live lease of one session: the session's terminal ended, so its subscription carries one session fewer and the next lease can go there. Releasing what is not live is not an error: a release the caller repeats releases nothing and says so.

Invocation¶

brama subscription lease release (--lease-id <ID> | --session-id <ID>) (--gateway <ORIGIN> | --gateway-consumer <NAME>) [--bearer-role <ROLE>] [--json]
InputRequired/defaultMeaning
--lease-id <ID>one of the two requiredThe lease to end, as take printed it.
--session-id <ID>one of the two requiredThe session whose every live lease ends.
--gateway <ORIGIN> or --gateway-consumer <NAME>one requiredThe gateway that holds the pool (DELETE /v1/subscription-pool/leases). The console bearer is read from stdin, or from the vault item playing --bearer-role.
--jsonoptional; offPrint {released: [lease...]} instead of lines.

Output and state¶

One line per lease released, then released <n>; or nothing was live under that name; nothing released. The gateway removes the released leases from its register.

Refusals¶

Naming neither a lease nor a session is refused by the parser before any request. A gateway refusal exits 1 and prints its error document: 400 invalid_request when the body names nothing (a release names the lease id or the session_id whose leases end), 503 with the cause when the register cannot be read or written. Without a gateway: a lease lives on the gateway that holds the pool: name --gateway or --gateway-consumer.

The real test is tests/subscriptions/leases.sh. See the command group or the CLI tree.
