Brama CLI command reference

brama subscription lease take¶

Take a lease for one session: the gateway records which subscription the session runs on, choosing the usable member of the provider that carries the fewest live sessions, so a machine's sessions are spread over the pool instead of all spending one account. The program that starts the session takes the lease before the harness starts (Oko does, for every session it starts or resumes) and releases it when the terminal ends. A session that already holds a live lease on the provider gets that lease back: a harness restarted by its own runtime is the same session.

Invocation¶

brama subscription lease take <PROVIDER> --session-id <ID> --holder <PROGRAM> (--gateway <ORIGIN> | --gateway-consumer <NAME>) [--bearer-role <ROLE>] [--json]
InputRequired/defaultMeaning
<PROVIDER>requiredThe provider the session will run on, for example claude-code.
--session-id <ID>required, nonemptyThe session that will run on the lease, as its runtime names it.
--holder <PROGRAM>required, nonemptyThe program taking the lease for the session (oko).
--gateway <ORIGIN> or --gateway-consumer <NAME>one requiredThe gateway that holds the pool (POST /v1/subscription-pool/leases); a lease lives nowhere else. The console bearer is read from stdin, or from the vault item playing --bearer-role.
--jsonoptional; offPrint the lease document instead of lines.

The choice¶

The limit is the operator's own number that the provider's declaration in src/subscription_dispatch/acquire/providers.json names (sessions_per_subscription_max for claude-code), in src/subscription_dispatch/acquire/numeric-provenance.json with his words beside it. The usable members are the provider's active, non-retired members the ledger holds nothing against (no grant awaiting a sign-in, no standing block). Among them the one carrying the fewest live leases is chosen; among equals, the one whose plan is least used. A member at the limit is passed over.

Output and state¶

One line per lease — <lease id> <provider> <subscription> (<account>) session <id> held by <holder> since <instant> — then taken: <n> of <limit> sessions on <subscription>, or already held: for a session's standing lease. With --json the document is {lease: {id, provider, subscription_id, account, session_id, holder, taken_at_ms}, live_on_subscription, limit, new}. The gateway writes the lease to its register (BRAMA_SUBSCRIPTION_LEASES_FILE, or leases.json under BRAMA_STATE_DIR), and brama subscription list shows each member's live_sessions.

Refusals¶

Every refusal exits 1 and prints the gateway's error document: the gateway refused: HTTP <status>: {"code", "message", "details"}. 409 pool_full: every usable member carries the limit; details.refusal.members lists each with its count, and details.acquisition is the verdict of the acquisition the gateway started for that shortage (acquired, refused with its code, or failed), so the caller reads whether a new account is on its way. 400 invalid_request: no provider, session or holder. 503 no_usable_member: the provider has no usable member, each named with what the ledger holds against it. 503 limit_unstated: providers.json declares no such provider (naming the ones it declares), or numeric-provenance.json states no number the declaration names, ending so no lease can be shared out. 503 dependency_unavailable: the inventory or the register could not be read or written, with the cause. Without a gateway: a lease lives on the gateway that holds the pool: name --gateway or --gateway-consumer.

The real test is tests/subscriptions/leases.sh. See the command group or the CLI tree.
