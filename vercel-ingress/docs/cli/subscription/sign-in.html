Brama CLI command reference

brama subscription sign-in¶

Ask Weles to sign one provider account in, then prove the repair by running Brama’s refresh path.

Invocation¶

brama subscription sign-in <PROVIDER> --reason <REASON> [--subscription-id <ID>] [--login-item <LOGIN_ITEM>] [--login-timeout-ms <MILLISECONDS>] [--json]
InputRequired/defaultMeaning
<PROVIDER>requiredOne of codex, claude-code, or kimi.
--reason <REASON>requiredNonempty audit reason recorded with sign-in and refresh verdicts.
--subscription-id <ID>optional only when exactly one active subscription matchesThe Skarbiec subscription to authenticate. Automatic renewal always supplies it.
--login-item <LOGIN_ITEM>optionalAn exact Skarbiec login reference. Otherwise the identity and login method are resolved from Skarbiec; no Weles account registration is required.
--login-timeout-ms <MILLISECONDS>optional; 900000Maximum time Weles may spend driving the browser.
--jsonoptional; offPrint JSON instead of labeled lines.

Output and state¶

Brama calls Weles's authenticated POST /reauth/resolve to resolve the exact Skarbiec identity without opening a browser. It passes the resulting account_revision to POST /reauth, checks the response and refreshes the persisted credential. The recorded outcome retains both the Skarbiec account revision and the Weles software source_revision, along with the subscription, login reference, failed stage, HTTP status and Weles run id. This command is optional; automatic renewal uses the same implementation without an operator action.

Brama Desktop's explicit Sign in action targets the selected account through POST /v1/admin/subscription-pool/sign-in, POST /v1/admin/subscription-sign-in/:agent_id/:subscription_id, or POST /v1/account/subscription-sign-in/:subscription_id. The body names a nonempty reason, optional login_item and optional login_timeout_ms; the pool route additionally requires subscription_id. Brama verifies ownership and derives the provider from that subscription. The app does not launch a local browser, and neither listing nor refreshing usage invokes this action.

Exact refusals¶

  • Unsupported provider: Weles does not support subscription authentication for <provider>.
  • Empty reason: --reason must say why this sign-in is being run.
  • Missing admission credential: BRAMA_WELES_REAUTH_TOKEN is unavailable; Brama must acquire brama-weles-reauth/token from Skarbiec at startup.
  • Identity failures name the Skarbiec subscription and distinguish subscription_identity_missing, skarbiec_login_missing, conflicting login material and a changed account revision.
  • Weles execution failures retain the actual failure.code, stage, provider HTTP status and run_id. An unreadable or lost execution response is unconfirmed, not proof that no browser ran.

An unconfirmed Weles response or a refresh that obtains nothing returns a failed verdict and exits 1; Brama never guesses between accounts.
