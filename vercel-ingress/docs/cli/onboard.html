Brama CLI command reference

brama onboard¶

Run Brama’s first-use journey, optionally adopt reviewed routes the user already has, and, only with explicit cost acknowledgement, request one real model response.

Invocation¶

brama onboard [-m <ROUTE>|--model <ROUTE>] [--agent-id <ID>] [--allow-provider-cost] [--reset]
  [--adopt-from <FILE> [--adopt-into <FILE>]
   [--adopt-apply (--adopt-select <ALIAS>... | --adopt-all-importable)
    [--adopt-replace-conflicts]]]
InputRequired/defaultMeaning
-m, --model <ROUTE>optional; openai/defaultCanonical provider/model route for the first real response.
--agent-id <ID>optional; wisent-appWorkload whose separately provisioned provider credentials and tagged Skarbiec subscriptions are reviewed or used.
--allow-provider-costoptional; offAcknowledge one billable provider request. Adoption never uses this acknowledgement and never makes an inference.
--resetoptional; offDiscard recorded walkthrough progress and replay first use.
--adopt-from <FILE>optionalReview a regular, non-symlink, at-most-1-MiB schema-1 Brama inference-routes JSON file before continuing the journey. Without --adopt-apply, the command prints the review and stops.
--adopt-into <FILE>optionalOwner-only destination; defaults to BRAMA_INFERENCE_ROUTES_FILE, then ~/.config/brama/inference-routes.json.
--adopt-select <ALIAS>repeatableSelect exact aliases from the reviewed source.
--adopt-all-importableoptional; offSelect aliases classified as importable or already unchanged. Conflicts and rejected aliases are excluded.
--adopt-applyoptional; offAtomically persist the selected aliases through the same operation as brama adopt and Brama Desktop.
--adopt-replace-conflictsoptional; offReplace a reviewed alias conflict. Deployment-name conflicts remain non-replaceable.

Output and state¶

An adoption review reports configured acquisition identities, discoverable subscription identities, every reviewed alias with the one route behind it, and importable, unchanged, conflicting, or rejected disposition. Applying reports exact imported, unchanged, conflicting, and rejected counts, preserves unselected state, and writes once only after whole-document validation. It never copies credential material; Skarbiec and the existing standalone provider store retain ownership. A source registry written before the current document shape is brought forward with brama routes migrate.

The walkthrough then prints its remaining journey steps. Without cost acknowledgement it sends no provider request, exits 0, and persists in-progress state at ~/.local/state/brama/onboarding.json. With acknowledgement it prints the selected model, response, and token counts; neither a review nor a persisted route marks onboarding complete. Only a successful real response records completion.

Refusals¶

Adoption options without --adopt-from, a write option without --adopt-apply, an apply without a selection mode, invalid source data, unknown or duplicate selections, and invalid destination state print Configuration adoption error: <reason> and exit 1 before the onboarding journey advances.

Without cost acknowledgement the terminal guidance explains that no provider request was sent and onboarding remains in progress. A failed model call prints Model request failed: <reason> and Onboarding remains in progress because no model response was received.; with cost acknowledged the command exits 1. Journey failures print Onboarding error: <error> and exit 1.
