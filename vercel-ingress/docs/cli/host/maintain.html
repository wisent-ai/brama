Brama CLI command reference

brama maintain¶

Ask the serving gateway for one maintenance pass through POST /v1/admin/maintain. The gateway keeps no timers of its own; the host's Stado schedule decides how often this runs, and the pass runs inside the serving process because that process holds the usage ledger, the journal and the credentials.

Invocation¶

brama maintain (--gateway <URL> | --gateway-consumer <CONSUMER>) [--bearer-role <ROLE>] [--json] [< bearer]
InputRequired/defaultMeaning
--gateway <URL>one of the twoThe gateway's origin.
--gateway-consumer <CONSUMER>one of the twoResolve the gateway through stado service directory connect brama --consumer <CONSUMER>.
--bearer-role <ROLE>optionalRead the console bearer at the moment of the pass from the token field of the vault item that plays this role, through stado credentials get --role <ROLE> --field token. No item is named, so replacing the item changes nothing here. Without it the bearer is read from standard input.
--jsonoptional; offPrint the gateway's report as JSON instead of lines.

A scheduled pass, for example: stado schedule create --pinned-host <gateway host> --cron '* * * * *' 'brama maintain --gateway-consumer <consumer> --bearer-role <console bearer role>'.

Output and state¶

The pass reads every plan usage report that is due (no reading, a reset window, a reading naming no reset, or a failed last read), renews every grant whose stated expiry has passed, and takes a fresh readiness reading for /readyz. Lines read:

plan usage: <N> subscription(s), <N> read
  failed <subscription> (<provider>): <error envelope>
credentials: <N> subscription(s), <N> refreshed, <N> refused, <N> sign-in check(s) scheduled
readiness: ready=<bool> <reason>

When renewal could not list the credentials, the credentials line is credentials: <inventory error>. It exits 0 only when the gateway's report says ok: true.

SentenceExitMeaning
the parser's refusal for neither or both of --gateway and --gateway-consumer2The pass has to run in one serving gateway; nothing was contacted.

the item playing role <role> holds no value in its token field1The vault answered with an empty field.
