Brama CLI command reference

brama probe¶

On the gateway's own host, send one real completion per alias through the running gateway and report what each one answered. /health answering says the process started; this says whether a model answers through each alias.

Invocation¶

brama probe --bearer-role <ROLE#FIELD> [--agent <AGENT> --signing-role <ROLE#FIELD>] [--alias <ALIAS>]... [--json] --allow-provider-cost
InputRequired/defaultMeaning
--bearer-role <ROLE#FIELD>requiredThe vault role whose item holds the client bearer every request presents, and its field: the one live item tagged stado:role:<ROLE>, read through the entitlements router ~/.config/brama/service.env names, never printed and never put in an argument. No item is named, so replacing the item changes nothing here.
--agent <AGENT>optional; needs --signing-roleSign every request as this agent with the x-agent-id, x-agent-timestamp and x-agent-signature headers. A subscription selector alias such as best needs a signed request.
--signing-role <ROLE#FIELD>optional; needs --agentThe vault role whose item holds that agent's request-sign secret, and its field.
--alias <ALIAS>repeatable; every declared aliasWhich aliases to request. Without one, every alias the gateway declares — the list brama aliases reports — is requested.
--jsonoptional; offPrint the findings once as one JSON document instead of one line per step.
--allow-provider-costrequiredAcknowledge that each alias spends one short provider request.

Output and state¶

It tries 127.0.0.1:<PORT> when service.env declares PORT (no port is assumed: the launcher itself refuses to start without one), then the address the last boot announced in the gateway's log, and stops at the first that answers GET /health. Each alias then gets {"model": alias, "messages": [{"role": "user", "content": "say ok"}]} on POST /v1/chat/completions. Lines read health <status> at <address>, then <alias> <status> model=<served> said="…" for an answer, <alias> <status> <refusal body> for a refusal, or <alias> unreachable <error>. With --json: {"addresses": [{address, health | error}], "signing": null | {agent}, "aliases": [{alias, status, model, said | refusal | error}]}.

It writes nothing and changes no configuration. It exits 0 only when every requested alias answered 2xx.
