Brama CLI command reference

brama collect-task-quality¶

Send one deterministic check to each selected active stateless provider route so later task:<task> selection has quality evidence.

Invocation¶

brama collect-task-quality --agent-id <ID> --task <KEY> --prompt <TEXT> [--expected-exact <TEXT>] [--expected-contains <TEXT>] [--persist] [--max-models <N>] --allow-provider-cost
InputRequired/defaultMeaning
--agent-id <ID>requiredAgent whose subscription routes are checked.
--task <KEY>required, nonemptyKey later selected as task:<task>.
--prompt <TEXT>required, nonemptyPrompt sent to every selected route.
--expected-exact <TEXT>one expectation requiredScore 1 only for an exact response.
--expected-contains <TEXT>one expectation requiredScore 1 when the response contains the text.
--persistoptional; offWrite check rows for later task selection.
--max-models <N>optional; 3Bound selected models to 1 through 25.
--allow-provider-costrequired by runtime; offAcknowledge all billable requests.

Output and state¶

The command prints one JSON report with agentId, task, persistence flag, bounds, per-model checks, and best-model results. Each selected model receives one provider request through the agent subscription path. With --persist, check rows are added to task-quality state; otherwise no quality rows are written.

Exact refusals¶

  • refusing billable task-quality collection without explicit cost acknowledgement
  • max_models must be between one and 25
  • task is required
  • prompt is required
  • expected_exact or expected_contains is required

Each refusal prints to stderr and exits 1; Clap separately refuses omitted CLI-required flags before the handler runs.

See task selectors or the CLI tree.
