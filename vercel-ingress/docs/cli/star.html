Brama CLI command reference

brama star¶

Read, dismiss or restart the request for a GitHub star that Brama makes once, after the fifth model call a provider answered.

Invocation¶

brama star status [--json]
brama star dismiss [--json]
brama star reset [--json]

status reads the request; dismiss stops it from being made; reset sets the count back to zero, so the request is made again after five answered calls. --json prints the same status as one JSON object.

Output and state¶

Each call a provider answers counts: test, decide, review (whatever its verdict), image, speak, music and video start. A refused call, every command that asks no provider, and a call whose standard error is not a terminal (a script, a pipe, an agent: nobody would read the request) do not count. The call that brings the count to five prints the request once on standard error, so standard output and --json keep only the answer: ★ Star Brama on GitHub: You have used Brama 5 times. If it helps you, a star on GitHub helps other people find it. https://github.com/wisent-ai/brama and `brama star dismiss` stops this message.

The request is the star-request journey every Wisent product walks, run by the shared onboarding runtime (Echo onboarding), and kept per user in $XDG_STATE_HOME/brama/onboarding.json (default ~/.local/state/brama/onboarding.json). Every verb that writes holds onboarding.json.lock beside it, so two Brama processes finishing at once both count; status writes nothing. The status names product, stage (counting, shown or dismissed), actions, threshold, repository and file. It contacts no provider and costs nothing.

Refusals¶

  • A journey file that holds no journey state is refused by every verb as storage unavailable: <file> is not a journey state: <cause>; `brama star reset` sets it aside and counts from zero; reset moves it to <file>.unreadable-<uuid> beside it and says so on standard error.
  • Neither XDG_STATE_HOME nor HOME set is refused as storage unavailable: neither XDG_STATE_HOME nor HOME is set, so the star request has no file to be kept in.
  • A call whose count cannot be kept still prints its answer and exits as it would; standard error says brama: this run is not counted toward the GitHub star request: <cause>.
