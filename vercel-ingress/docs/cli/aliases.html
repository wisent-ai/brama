Brama CLI command reference

brama aliases¶

Report every model alias this gateway declares, the route behind it, and whether the gateway can serve it right now — and, when it cannot, why not.

Invocation¶

brama aliases [--json] [--strict]
InputRequired/defaultMeaning
--jsonoptional; offPrint the report as JSON instead of human-readable lines.
--strictoptional; offExit 1 after printing when any declared alias cannot be served; for gates and health probes.

What it reads¶

The same two sources the gateway reads at startup: the launcher's alias table in BRAMA_MODEL_ALIASES, when this process was started with it, and the route registry file named by BRAMA_INFERENCE_ROUTES_FILE. When that variable is unset the command reads the launcher's default path, ~/.config/brama/inference-routes.json, so an operator shell sees the file the gateway on this host serves from. The first two lines of text output name both sources, because a shell that has neither is looking at the compiled-in contract alone and must say so. The command contacts no provider and writes nothing.

Output and state¶

One row per alias — the compiled-in contract plus every operator-declared route — with the state word the gateway itself uses, the one route behind the alias, and the reason on a second line when the alias cannot serve. Captured on 2026-09-05:

route registry: /Users/lukaszbartoszcze/.config/brama/inference-routes.json
launcher alias table: absent; only the compiled-in contract and the route registry are visible here
best                             serving              best
ox-alpha                         capability_absent    openrouter/stealth/ox-alpha
                                 alias `ox-alpha` routes to openrouter/stealth/ox-alpha but this gateway holds no provider credential for openrouter; issue the provider capability on this host or point the alias at a route it can reach, such as `best`
weles                            no_route             -
                                 alias `weles` is required by this gateway but no route is declared for it; declare one with `PUT /v1/admin/routes` or in the launcher's model_aliases policy
wisent-backend      serving              local-openai/chat-primary
9 alias(es), 4 cannot be served

States are serving, no_route, capability_absent and routes_file_invalid; their meaning and repair are in the alias concept. best is a subscription selector, not a route, so it is reported serving with no route table entry. JSON output carries source, aliases and unserviceable; the same table for a running gateway is GET /v1/aliases, whose rows are alias, state, route, reason, required and authorized. A registry the gateway refuses whole reports routes_file_invalid, and brama routes migrate rewrites such a document into the current shape.

Refusals¶

aliases could not be read: <reason>, exit 1, when the alias table or the route registry file cannot be parsed; the reason is the parser's own sentence. With --strict the command exits 1 after printing when unserviceable is above zero. Clap refuses unsupported options before anything is read.
